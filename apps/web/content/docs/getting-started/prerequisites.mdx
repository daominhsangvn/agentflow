## The server machine

The server runs the web app (port 3000), the API (3002) and the MCP server (3010) with Node.js, and the backing services with Docker.

| Requirement | Version | Notes |
|---|---|---|
| Node.js | 24 or newer | Required by the repository's `engines` |
| pnpm | 11.7.0 | Pinned in `packageManager`; run `corepack enable` |
| Docker | Recent | Runs Postgres, RustFS, Mailpit and Local Git |

```bash
corepack enable
```

## URLs

- **An API URL your Agents can reach over HTTPS.** The API key travels over this connection, so plain HTTP is refused except for localhost and the hosts you list in `AGENTFLOW_ALLOW_HTTP_HOSTS` (only for a network you trust, such as `host.docker.internal` with Docker Desktop).
- **A public HTTPS URL for Jira webhooks**, set as `PUBLIC_WEBHOOK_BASE_URL` on the API. Jira Cloud only calls public HTTPS URLs. On a machine without one, set the Jira connection to **poll** mode; poll mode only sees issues assigned to the bot, so labels, status changes and mentions need a webhook.

## Claude credentials

Every Agent runs Claude Code. Provide one of:

- A Claude subscription token: `CLAUDE_CODE_OAUTH_TOKEN`, created with `claude setup-token` on any machine with a browser.
- `ANTHROPIC_API_KEY` on the Agent.
- An Anthropic-compatible provider (base URL, token, default model) set in AgentFlow on the Agent's **Model provider**. It is stored sealed and sent with each task; it wins over the Agent's own credentials.

## Bot accounts

AgentFlow writes to outside systems as a bot. Create an account for each system you use:

- Jira (and Confluence, if people review documents there): a bot user with an API token.
- Your Git server: a token for the bot. Local Git (Gitea, started by Docker) is included for projects without a remote.

Changes the bot makes are ignored as triggers, so it never starts itself. See [Connections](/docs/guides/setup/connections) for the exact permissions.
