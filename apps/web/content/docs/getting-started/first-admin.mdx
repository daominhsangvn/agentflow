## The first account

Open the web app (http://localhost:3000) and sign up. Accounts are local email and password accounts.

- The first account creates the organization (`AUTH_DEFAULT_ORGANIZATION_NAME` and `AUTH_DEFAULT_ORGANIZATION_SLUG`, default `AgentFlow` and `agentflow`) and becomes its owner.
- Later accounts join it as members. Set `AUTH_AUTO_JOIN_DEFAULT_ORGANIZATION=false` to stop that; an invitation for their email can still give them another role.
- Owners and admins invite people from **Settings → Organization**. The email links to sign-up with the address filled in.
- `AUTH_ALLOW_SIGN_UP=false` makes the deployment invite-only: only emails with a pending invitation can sign up.
- `AUTH_ALLOW_CREATE_ORGANIZATION=true` allows more than one organization.

Invitations and password resets are sent over `SMTP_URL`. In development, read them in Mailpit at http://localhost:8025.

## Admin-only work

Connections, project connections and workflows are admin-only. Do the rest of the setup as an organization admin.

## Create a project

Click **New project** in the sidebar. The project is where a team's connections, repositories, Agents and workflows come together; give it a clear name.

## Create an API key for Agents

Open the account menu → **Settings → API Keys** and create a key with the `write` scope. An Agent registers as a compute target of the key's owner, so a dedicated bot user is a good owner. Copy the key when it is shown; you pass it to the Agent as `AGENTFLOW_API_KEY`.
