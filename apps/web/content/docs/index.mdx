AgentFlow is a self-hosted platform where AI Agents deliver tickets and people review at milestones. You connect your Jira, Confluence and Git server, describe in plain language how a ticket should be handled, and a team of Agents does the work. People stay in charge: they answer questions, move statuses, edit pages and merge pull requests.

## How a ticket flows

```
Jira ticket ──▶ Workflow ──▶ Orchestrator Agent ──▶ BA / Dev / QC Agents run commands
 (status move,   (triggers)    (follows your rules     (Claude Code on their machine)
  @mention)                     in plain language)                │
       ▲                                                          ▼
       └──── people answer, move statuses, edit pages, merge ◀── Confluence pages,
                                                                  Git pull requests,
                                                                  ticket comments
```

A **workflow** decides what starts work. In an orchestrated workflow, every request goes to the **Orchestrator Agent**, which reads your rules and the history of the ticket, then sends commands to the BA, Dev and QC **Agents**. Their results are written back as Confluence pages, pull requests and ticket comments. People review each milestone and the Orchestrator Agent continues from their answer.

## An example: LD-6

The running example is LeaveDesk ticket LD-6, "As a manager I want a calendar of who in my team is off". One ticket goes from To Do to Done: the BA Agent writes a PRD that people refine through four versions (v1 to v4), planning runs in parallel, there are two test rounds, then review and Done. The ticket produced Confluence pages (PRD, implementation plan, test plan, test runs), three pull requests and short comments in Jira.

## What runs where

| Part | What it is |
|---|---|
| Server | The web app (:3000), the API (:3002) and the MCP server (:3010), plus Postgres, RustFS (object storage), Mailpit (development mail) and Local Git from `docker-compose.yml` |
| Automatic Agent | A headless Agent on a server or in a container. It clones the project's repositories and works with AgentFlow's credentials |
| Personal Agent | An Agent on a person's own machine, in the project folder they already use, with their own credentials |

Every Agent runs Claude Code. Agents reach the API and the MCP server, and never hold your Jira, Confluence or Git credentials: AgentFlow calls those systems for them.
