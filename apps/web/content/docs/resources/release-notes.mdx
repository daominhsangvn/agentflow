## 2026-11-16

- Asking people in Teams: an Orchestrator Agent granted a Teams key `ask` asks people in the project connection's **Ask channels** (`teams_ask`), discusses in the thread (`teams_ask_reply`) and records the answers only after an asked person confirms its summary (`teams_ask_confirm`). A case keeps one thread per ask channel. See [Microsoft Teams](/docs/integrations/microsoft-teams#asking-people-orchestrated-workflows).
- An approval or sign-off at the end of a personal Agent's command becomes a question with Approve / Request changes (`asks: true`); without `asks` the agent never approves on people's behalf. See [Integrate an existing agent](/docs/guides/setup/integrate-existing-agent).
- `jira.issue_status_changed` takes a `labels` filter. See [Triggers and actions](/docs/guides/setup/triggers-and-actions).
- `AUTH_MICROSOFT_TRUST_EMAIL=true` trusts the Microsoft `email` claim for a specific tenant whose users carry no verified-email claim. See [Server environment variables](/docs/reference/server-env).
- Logging: `LOG_LEVEL` on the server and the Agent. Agents send their traces, logs and metrics to the API by default (`AGENTFLOW_RUNNER_TELEMETRY=false` opts out), which forwards them to SigNoz when an OpenTelemetry endpoint is set.
- On Windows the Agent and its System Check find Python 3 as `python3`, `python` or `py -3`.
- Fixes: open cases keep refreshing so new messages show without reloading; Teams messages are read from their HTML content; Teams ask channel ids keep their case.

## 2026-11-01

Self-hosted edition as it stands.

- Projects connect to Jira, Confluence, Bitbucket, Local Git and other integrations through project connections and connection grants.
- Orchestrated workflows: an Orchestrator Agent follows rules written in plain language and starts tasks for Agents.
- Projects belong to the organization; teams are gone.
- Workflows show case counts. Cases have a run-style list and detail page.
- Task guards refuse undeclared commands, write tasks of read commands and writes from a superseded turn. Refused calls show on the case.
- Agents report their Claude Code version, and personal Agents get the `claude install` command when it differs from the pinned one.
- Blockers: `source_item_get` returns `blockedBy` / `blocks` from Jira "Blocks" links and Azure DevOps Dependency relations. The new orchestrator tool `case_notify` leaves a "Case notice" on another case of the workflow and wakes it, so a waiting case can continue when its blocker is done.
- New setup guide for orchestrated workflows, with the LeaveDesk example.
- New navigation: Home, Cases, Runs, Sessions, Workflows, Agents and Connections. Projects have the tabs Overview, Workflows & Cases, Agents, Connections & Repos and Instructions.
