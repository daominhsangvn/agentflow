## What it does

GitHub provides **repositories** and the `github.create_pull_request` action. It has no triggers and no inbound side yet.

## Connection settings

| Key | Notes |
|---|---|
| `config.apiUrl` | Leave the default (`https://api.github.com`) for github.com; `https://<host>/api/v3` for GitHub Enterprise Server |
| secret `token` | A fine-grained personal access token of the bot account, with access to the repositories projects will use and Contents and Pull requests set to Read and write |

Saving the connection checks the token; its owner is the bot.

## Repositories

Project → **Connections & Repos** → add a repository → choose the GitHub connection, search, add. Archived repositories are left out. A project has at most 20 repositories. Agents clone and push with credentials AgentFlow gives each run; the repository stores no token.

## Pull requests

`github.create_pull_request` opens one pull request in each repository of the run that the Agents pushed a branch to, from that branch into the configured target branch (else the branch the run started from, else the default branch). It reuses the open pull request of the same head and base. An orchestrated workflow uses the `pull_request_open` tool instead. A project with repositories on two providers needs the action of each connection. See [Triggers and actions](/docs/guides/setup/triggers-and-actions).

## Limits

- Merging a pull request on GitHub is not reported back to AgentFlow.
- At most 1000 repositories are listed.
